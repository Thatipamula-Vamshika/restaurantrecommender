## Plan: CommunalTable v3 — visuals, themes, menus, maps, sentiment

I'll ship these eight changes in one pass. Below is what each touches and how.

### 1. Animated hero (GSAP-style)
- Add a hero with a **floating, parallax stack of food photos** that drift on mousemove + a subtle continuous float, plus a kinetic word-marquee behind the title (already partially there — upgrade with real motion).
- Animate the **CommunalTable logo wordmark**: letter-by-letter staggered reveal on mount + slow rotating plate emoji.
- Pure CSS keyframes + a tiny `mousemove` listener — no GSAP dependency needed (keeps bundle small).

### 2. More themes + per-theme group flow
- Expand `THEMES` from 4 → **10**: Family, Pet-friendly, Romantic, Casual, Birthday, Business lunch, Late night, Brunch, Solo treat, Healthy bowl.
- On the theme tile, clicking **opens `/theme/$theme`** which already lists restaurants of the chosen city. I'll add a **"Start a group in this vibe"** button that deep-links into the collect flow with theme + city pre-selected (URL search params).

### 3. "View full menu" link
- In `restaurant.$id.tsx` and result cards, add an explicit **"View full menu →"** button that opens a Google search scoped to Zomato/Swiggy menu pages: `site:zomato.com OR site:swiggy.com {name} {city} menu`. (We have no real menu data; this is the most reliable shortcut to a real menu.)

### 4. Map-based location detection (English)
- Replace the plain "Use my location" button with an **embedded Leaflet map** (via free OSM tiles, no API key). User clicks on the map → marker drops → reverse-geocode via Nominatim with `accept-language=en` so labels are in English.
- Library: `react-leaflet` + `leaflet`.

### 5. Free-text allergies
- Keep the toggle chips for the common ones, add a **text input "Add another allergy…"** that appends custom tokens to the member's allergy list. Recommender already filters by raw token substring, so custom allergies just work.

### 6. More varied restaurant photos
- Expand `PHOTOS` in `restaurant-media.ts` from 20 → ~60 images, and **bias selection by cuisine** (e.g. biryani photos for biryani restaurants, pizza for pizzerias, thali for Indian, etc.). Function signature gains an optional `cuisines` arg.

### 7. Sentiment-driven feedback loop
- After results, show **"Tell us what you thought"** textarea. On submit, call a new server fn that uses Lovable AI (`google/gemini-3-flash-preview`) to extract: sentiment (−1..1), liked cuisines, disliked cuisines, price reaction.
- Store the parsed result in `localStorage` keyed by city (privacy-friendly, no auth needed). On next session for that city, **boost liked cuisines** and **down-weight disliked** in `recommend()` via an optional `feedbackBoost` param.
- Requires enabling Lovable Cloud (for `LOVABLE_API_KEY`). I'll enable it.

### 8. Per-city default recommendations
- Build `src/lib/city-defaults.ts` at runtime: group the 60K dataset by city → top 5 highest-rated per city → cache in a generated `public/city-defaults.json` (small, ~5KB).
- `recommend()` fallback already exists; I'll route the empty-result path through this per-city default so **every city always returns something**.
